# Коммутаторы Catalyst 1000

Обе модели в магазине представляют реальные коммутаторы Cisco без PoE
и вентиляторов. Оборудование задаётся в `assets/equipment/switches.json`;
4X создаётся по собственному профилю, а не преобразуется из купленного 4G.
Существующие идентификаторы покупок и игровые цены сохраняют совместимость
с сохранениями.

| Характеристика | C1000-24T-4G-L | C1000-24T-4X-L |
| --- | --- | --- |
| Медные порты | 24 × 10/100/1000 RJ45 | 24 × 10/100/1000 RJ45 |
| Оптические аплинки | 4 × 1G SFP | 4 × 1/10G SFP+ |
| Имена медных интерфейсов | Gi1/0/1–24 | Gi1/0/1–24 |
| Имена интерфейсов аплинков | Gi1/0/25–28 | Te1/0/1–4 |
| Заявленная коммутационная ёмкость | 56 Гбит/с | 128 Гбит/с |
| Заявленная скорость пересылки | 41.67 млн пакетов/с | 95.23 млн пакетов/с |
| Опубликованное потребление в простое / при 100% трафика | 15.84 / 22.80 Вт | 18.00 / 25.68 Вт |
| Масса | 2.63 кг | 2.78 кг |

Обе модели используют процессор ARM v7 800 МГц, 512 МБ DRAM и 256 МБ
флеш-памяти. Указанные значения — характеристики производителя, а не результаты
измерений этого детерминированного симулятора. Симуляция электропотребления
интерполирует значения между простоем и полной нагрузкой трафиком с учётом
ёмкости активных соединений и недавней скорости передачи байтов, отдельно
добавляет нагрузку установленных трансиверов, затем округляет до целых ватт.
Один ping оставляет потребление близким к простою. Подробности расчёта см.
в [руководстве по энергопотреблению](POWER_CONSUMPTION.md). Подробности товара
в магазине и `show version` показывают исходные значения вместо старой
универсальной оценки 80 Вт.

У 4X собственная фотография передней панели и координаты центров медных
разъёмов. Соответствующий задний корпус без вентиляторов использует общее
изображение задней панели. Источники изображений и характеристики приведены
в [ATTRIBUTION.md](../assets/equipment/ATTRIBUTION.md).

## EtherChannel

На двух соединённых коммутаторах настройте порты с одинаковой скоростью
и совпадающими параметрами access VLAN либо trunk, native VLAN и разрешённых
VLAN. Например, соедините Gi1/0/1 и Gi1/0/2 между коммутаторами, затем
на каждом выполните:

```text
enable
configure terminal
interface range Gi1/0/1 - 2
channel-group 1 mode active
end
show etherchannel summary
show etherchannel 1 detail
show interfaces Port-channel1
```

Группы 1–6 поддерживают статический режим `on`, LACP `active`/`passive`
и PAgP `desirable`/`auto`. Пары passive/passive и auto/auto не образуют канал.
Для статических соединений нужен `on` на обоих концах. LACP поддерживает
восемь активных участников и до восьми участников в горячем резерве;
остальные режимы поддерживают восемь участников. Локальные номера групп
на двух концах могут различаться.

`lacp system-priority` и интерфейсная команда `lacp port-priority` определяют
активных участников LACP. Каждый поток использует одного участника,
а широковещательный пакет проходит через объединённый канал один раз.
Отказ соединений вызывает детерминированный выбор участников и переключение
пересылки по MAC. Spanning Tree рассматривает объединённый канал как одно
соединение с суммарной ёмкостью.

```text
configure terminal
port-channel load-balance src-dst-mac
interface Port-channel1
port-channel min-links 2
end
```

Другие варианты хеширования — `src-mac` (по умолчанию) и `dst-mac`.
Min-links принимает значения 2–8; `no port-channel min-links` восстанавливает
значение по умолчанию — одно соединение. Команда `shutdown` на логическом
интерфейсе отключает объединённый канал. Команды VLAN и скорости на логическом
интерфейсе атомарно применяются к его физическим участникам. `no channel-group`
удаляет физический интерфейс из объединённого канала. Согласование представляет
собой установившееся состояние, рассчитанное по конфигурации и наличию
физического соединения, а не обмен сообщениями LACP/PAgP с временными задержками.

## QoS

По умолчанию QoS отключён и сохраняет маркировку пакетов. После включения порты
по умолчанию не доверяют входной маркировке: входящие DSCP и CoS сбрасываются
в настроенное значение CoS по умолчанию (ноль, если оно не изменено).
Явно настройте доверие DSCP для IP-трафика или CoS для трафика с тегами:

```text
configure terminal
mls qos
interface Gi1/0/1
mls qos trust dscp
interface Gi1/0/2
priority-queue out
srr-queue bandwidth share 25 25 25 25
srr-queue bandwidth limit 50
end
show mls qos interface Gi1/0/2 statistics
```

Имеются четыре выходные очереди. По умолчанию CoS сопоставляется так:
0/1 → очередь 2, 2/3 → очередь 3, 4/6/7 → очередь 4 и 5 → очередь 1.
Командой `mls qos srr-queue output dscp-map queue 1 46` можно переопределить
до восьми значений DSCP за один вызов. Интерфейсная команда `mls qos cos 3`
задаёт CoS по умолчанию; `no mls qos trust` возвращает классификацию
без доверия к маркировке. `no mls qos` восстанавливает передачу без изменения
маркировки и отключает ограничение скорости.

Взвешенное обслуживание очередей и необязательный строгий приоритет очереди 1
действуют в пределах пакетных групп (`NetworkSim::transmit_frames`).
Ограничение исходящего трафика принимает 10–90% согласованной скорости
соединения, использует бюджет токенов по времени симуляции со всплеском
длительностью 10 мс (минимум один MTU) и считает переданные пакеты, байты
и потери по каждой очереди. Изменения DSCP сохраняются в IPv4-пакете
при маршрутизируемой пересылке. Это семантическая модель очередей,
а не планирование ASIC, пороги WTD или физические буферы;
очереди пакетов с задержкой по реальному времени нет.

## SNMPv2c

Задайте коммутатору доступный IP-адрес управления и настройте community:

```text
configure terminal
management ip 10.0.0.2
snmp-server community monitor ro
snmp-server community operator rw
snmp-server contact Ops team
snmp-server location Rack 1
end
show snmp
```

На моделируемом сервере Linux с IP-адресом и сетевым путём к этому коммутатору:

```text
snmpget -v 2c -c monitor 10.0.0.2 sysDescr.0
snmpget -v 2c -c monitor 10.0.0.2 ifHighSpeed.25
snmpwalk -v 2c -c monitor 10.0.0.2 1.3.6.1.2.1.2.2.1.2
snmpset -v 2c -c operator 10.0.0.2 sysLocation.0 s Rack1
```

Системные OID предоставляют модель, время работы конкретного устройства,
имя узла, контакт и местоположение. IF-MIB предоставляет имена интерфейсов,
скорость, MTU, административное и рабочее состояние, а также реальные
счётчики байтов симулятора. Счётчики октетов высокой ёмкости и `ifHighSpeed`
показывают 10G без 32-битного переполнения. Индексы интерфейсов — 1–28;
индекс 25 обозначает первый аплинк у обеих моделей (его имя в IOS различается).
Доступны для записи sysName, sysContact, sysLocation и ifAdminStatus
(`i 1` — включён, `i 2` — выключен). Неизвестные OID и запись без полномочий
завершаются явной ошибкой.

Запросы проверяют ARP, маршруты, VLAN, физическое соединение, питание
коммутатора, фильтрацию UDP/IP и права community. Эти команды используют
детерминированный путь управления игры. Они не открывают сокеты хостовой ОС
и не реализуют кодирование BER, traps, SNMPv3, community с привязкой к ACL
или полный набор MIB.

## Сохранения и перезагрузка

Настройки EtherChannel, QoS и SNMP сохраняются вместе с миром и командами
`write memory` / подтверждённой `reload`. Счётчики очередей и SNMP относятся
к рабочему состоянию и сбрасываются при загрузке или перезагрузке;
отсчёт времени работы начинается при включении питания устройства.
Старые сохранения 4X восстанавливают модель по существующему идентификатору
оборудования, преобразуют имена и описания Te1/0/25–28 в Te1/0/1–4
и сохраняют идентификаторы портов, кабели, модули, VLAN и стартовые конфигурации.

и [обзор оборудования](https://www.cisco.com/c/en/us/td/docs/switches/lan/catalyst1000/hardware/installation/24_48_port_hig/b_c1000_24_48_hig/product_overview.html).

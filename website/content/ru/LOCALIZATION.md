# Локализация

Выберите **Settings → Language → English / Русский**. Язык сохраняется в
`cloud-provider-settings.json`. Для старых файлов настроек по умолчанию используется
английский. Смена языка не меняет конфигурацию устройств, сохранения или консольный
слушатель. Команды терминала, приглашения, история и вывод сохраняют исходный текст.

## Сообщения интерфейса

`assets/locales/en.json` и `ru.json` содержат стабильные семантические идентификаторы.
Английский текст всегда является значением, а не ключом. Изменение формулировки
не требует изменения идентификатора.

```json
{
  "language": "ru",
  "name": "Русский",
  "messages": {
    "settings.title": "Настройки",
    "cable.install-guide": "Купите кабель и разъёмы RJ45…",
    "game.saved-path": "Сохранено в {0}"
  }
}
```

Код интерфейса явно запрашивает сообщение и передаёт его аргументы:

```rust
tr("settings.title")
tr_args("game.saved-path", &[path.display().to_string()])
```

Шаблоны используют нумерованные аргументы (`{0}`, `{1}`). В переводе их можно
переставлять или повторять, но набор аргументов должен совпадать с английским
оригиналом. Для буквальных фигурных скобок используйте `{{` и `}}`. Аргументы
вставляются без изменений: например, заданное игроком имя `Settings` никогда
не интерпретируется как текст для перевода. Перечисления состояний явно выбирают
идентификаторы сообщений. Уведомления сохраняют идентификаторы и аргументы до
отрисовки, поэтому смена языка обновляет и существующие уведомления. Ошибки
симуляции сопоставляются по варианту перечисления, а не по английскому выводу
`Display`. Подробности системной диагностики выводятся без изменений.

Для отсутствующих сообщений используется английский текст; неизвестный
идентификатор отображается как `[id]`, чтобы ошибка была заметна. Некорректные
JSON, идентификаторы или несовпадающие подстановки записываются в журнал
и пропускаются.

## Переводы предметов

Названия и описания предметов принадлежат конфигурации самих предметов, а не
каталогу интерфейса. Накопители используют `assets/equipment/drives.json`,
серверные компоненты — `server_parts.json`, стоечное оборудование — существующие
`*_config.json`, а кабельные материалы — `supplies.json`. У каждого предмета
есть идентификатор и поля с кодами языков:

```json
{
  "id": "enterprise_ssd_960gb",
  "name": "960 GB Enterprise SATA SSD",
  "display_name": {
    "en": "960 GB Enterprise SATA SSD",
    "ru": "Серверный SATA SSD 960 ГБ"
  },
  "desc": {
    "en": "Enterprise solid-state drive for fast storage.",
    "ru": "Серверный твердотельный накопитель для быстрого хранения данных."
  }
}
```

Существующее строковое поле `name` у накопителей и компонентов — внутреннее
название модели, используемое симуляцией и терминалами; `display_name` — его
представление в интерфейсе. Числовые характеристики и идентификаторы моделей
не зависят от перевода. Текст интерфейса выбирается по идентификатору предмета
и текущему языку; при отсутствии перевода используются английские поля этого
предмета. Имена, заданные пользователем, сохраняются. Магазин отображает
локализованные названия и описания и использует их при поиске.

Чтобы добавить язык, скопируйте существующий файл локализации, задайте `language`
и название языка на нём самом в поле `name`, затем переведите значения сообщений.
При необходимости добавьте тот же код языка в поля предметов. Переключатель
в Settings обнаруживает каталоги при запуске. Внешние JSON-переопределения
загружаются из каталога ресурсов; после редактирования файлов перезапустите игру.
При отсутствии файлов используются встроенные каталоги и метаданные предметов.
Переносимые пакеты включают каталоги локализации и оборудования.

Симуляция владеет только метаданными ресурсов с кодами языков; выбор языка,
загрузка внешних переопределений представления, форматирование шаблонов
и отрисовка текста относятся к игровому слою. Кадры интерфейса используют
неизменяемые снимки языка в своей области действия, поэтому отдельные потоки
интерфейса и тестов могут выбирать языки независимо друг от друга.

# Консоль гостевой Linux-системы

У каждого сервера есть собственное симулируемое окружение Linux в стиле Debian:
файлы, история оболочки, службы и состояние сети. Команда `help` показывает
реализованные команды. Это детерминированная игровая ОС, а не виртуальная машина
Linux: она не устанавливает и не запускает нативные исполняемые файлы. Описанные
здесь команды и флаги реализованы; произвольные пакеты Linux, полноценное
программирование на Bash, IPv6 и реальные интернет-службы в возможности этой
гостевой системы не входят.

## Настройка адресов и маршрутов

```sh
ip a
ip -br addr
ip link show
ip link set dev eth0 up
ip addr add 10.0.0.10/16 dev eth0
ip addr add 192.0.2.10/24 dev eth0
ip addr del 192.0.2.10/24 dev eth0
ip route
ip route add 198.51.100.0/24 via 10.0.0.1 dev eth0 metric 100
ip route replace default via 10.0.0.1 dev eth0
ip route get 198.51.100.5
ip route del default
ip neigh show dev eth0
ip neigh flush dev eth0
ping -c 3 -I eth0 10.0.0.20
traceroute 10.0.0.20
```

Адреса влияют на фактический симулируемый трафик Ethernet/ARP/ICMP.
Поддерживается несколько адресов на интерфейс. При выборе маршрута сначала
используется самый длинный префикс, затем наименьшая метрика.
`ip addr flush dev eth0` удаляет адреса интерфейса; `ip route flush` удаляет
явные маршруты и настроенные шлюзы, но оставляет маршруты непосредственно
подключённых сетей, выведенные из адресов. `-4`, `-br`, `-o` и `-s` выбирают
соответственно IPv4, краткий вывод, вывод в одну строку и статистику.

`mgmt0` — отдельный интерфейс управления ОС. Подключайте его через явно
заданные коммутаторы управления или патч-панели; сами по себе LAN-разъёмы стоек
не соединяют стойки. Имена сетевых интерфейсов передачи данных зависят от
установленных карт; проверьте их через `ip link`.

Публичные адреса не зависят от внешних каналов связи. Купите пул адресов
в магазине или окне **ДИАПАЗОНЫ IP**; выберите там канал предоставления диапазона
и следуйте инструкциям WAN/LAN, чтобы настроить интерфейсы маршрутизаторов
и прямые/обратные маршруты на каждом маршрутизаторе через **Таблица маршрутизации…**.
Изменения через гостевую команду `netctl` ограничены интерфейсами этой гостевой
системы; она не может настраивать другое устройство или оператора связи.
Полный пример маршрутизации приведён в
[руководстве по сети провайдера](PROVIDER_NETWORK_GUIDE.md).

## Постоянная настройка сети

`ip` изменяет текущую конфигурацию. Чтобы восстановить настройки после `reboot`,
запишите `/etc/network/interfaces` и запустите службу сети. В этом примере файл
создаётся через `printf`; замените адреса и имена на используемые в вашей топологии.

```sh
printf 'auto lo eth0 mgmt0\niface lo inet loopback\niface eth0 inet static\n address 192.0.2.10/24\n gateway 192.0.2.1\n post-up ip route add 198.51.100.0/24 via 192.0.2.254 dev eth0\niface mgmt0 inet dhcp\n' > /etc/network/interfaces
cat /etc/network/interfaces
systemctl restart networking
ip -br a
ip route
reboot
```

Поддерживаются методы секций `static`, `dhcp`, `manual` и `loopback` для `lo`.
Используйте адрес в формате CIDR либо адрес вместе с `netmask`. `auto` и
`allow-hotplug` выбирают интерфейсы для `ifup -a` и запуска службы сети.
`dns-nameservers` записывает `/etc/resolv.conf`; `post-up` и `up` выполняют
гостевые команды после настройки. Аренда DHCP требует доступного интерфейса
с явно настроенным пулом `netctl dhcp` и действующего пути для широковещательных
пакетов и ответов. Некорректный файл не изменяет работающую конфигурацию сети.

```sh
ifdown eth0
ifup eth0
ifup -a
systemctl status networking
journalctl -u networking
```

Файлы, службы, адреса и маршруты сохраняются в сохранениях игры. `reboot`
очищает текущие адреса и маршруты и повторно применяет включённую службу сети.
Файлы остаются. Обычное переключение питания в игре сохраняет записанную
конфигурацию.

## Оболочка и файлы

Поддерживаются одинарные и двойные кавычки, экранированные символы, `$NAME`,
`${NAME}`, `$?`, конвейеры, перенаправление ввода и вывода, дописывание,
`;`, `&&` и `||`.

```sh
mkdir -p /root/config
cd /root/config
export IFACE=eth0
ip -br a | grep "$IFACE" > interface.txt
cat interface.txt
echo '10.0.0.20 database.internal' >> /etc/hosts
getent hosts database.internal
ping database.internal
false && echo skipped || echo recovered
printf '#!/bin/sh\nip addr add 10.0.0.10/16 dev eth0\n' > setup.sh
chmod 755 setup.sh
./setup.sh
```

Файловые команды включают `pwd`, `cd`, `ls [-la]`, `mkdir [-p]`, `touch`, `cat`,
`cp`, `mv`, `rm [-rf]`, `rmdir`, `chmod` с восьмеричными правами доступа,
`find [-name PATTERN]`, `head`/`tail [-n COUNT]`, `grep [-inv]` с буквальными
шаблонами, `wc [-lwc]`, `sort [-ru]`, `uniq`, `tee [-a]`, `df` и `du`.
Сейчас `cp`/`mv` работают с файлами. `printf` поддерживает `%s`, `%d` и `%%`.
`sh FILE`, `bash -c 'COMMAND'`, `source FILE` и исполняемые гостевые скрипты
выполняют команды оболочки; скрипт останавливается при первой ошибке.
Полноэкранные редакторы, циклы и функции оболочки не реализованы.

Разрешение имён использует `/etc/hosts`, явно заданные IP-адреса и симулируемые
имена серверов. `getent hosts`, `nslookup` и `dig` проверяют это разрешение;
они не обращаются к внешним DNS-серверам. Адреса DNS-серверов можно сохранить
в конфигурации.

## Службы и SSH

```sh
systemctl list-units
systemctl status ssh
systemctl stop ssh
systemctl enable --now ssh
systemctl is-active ssh
service ssh restart
journalctl -u ssh
ss -lntp
ps aux
ssh root@10.0.0.20
hostnamectl
exit
```

`ssh` подключается по IP-адресу управления через `mgmt0` исходного сервера.
Остановленная служба SSH отклоняет новые подключения. После подключения
команды, гостевые файлы и приглашение оболочки принадлежат удалённому устройству.
`exit` закрывает сеанс. Сеансы коммутаторов и маршрутизаторов используют их
консоль IOS; IP-адрес управления коммутатора задаётся командой
`management ip ADDRESS` в режиме глобальной конфигурации. Сеансы SSH и
прослушивающие порты симулируются; аутентификации и реальной реализации TCP/SSH нет.

`systemctl` поддерживает status, start/stop/restart/reload, enable/disable
(`--now`), is-active/is-enabled (`--quiet`), list-units и list-unit-files.
Доступные службы: `ssh`, `networking` и `systemd-resolved`. `reboot`
восстанавливает состояние включённых служб. `shutdown`/`poweroff` выключают
устройство.

Команды для оборудования включают `lscpu`, `free -h`, `lsblk`,
`smartctl -a /dev/sda`, `ethtool [-i] IFACE`, `netstat -i`, `uname -a`,
`hostname` и `hostnamectl`. Используйте стрелки вверх/вниз для истории,
Tab для автодополнения команд, **Очистить вывод** или `clear` для очистки
и **Вставить команды** для последовательности строк консоли.

Подсказки Tab формируются активным объектом команды и её текущими аргументами.
Например, `ping -I` предлагает интерфейсы, `systemctl restart` — службы,
`cat` — гостевые файлы, а `ip route ... dev` — имена сетевых интерфейсов.
Подсказки также работают после конвейеров и условных операторов и внутри
незавершённых путей в кавычках.

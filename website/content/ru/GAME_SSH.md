# Отдельный клиент game-ssh

`game-ssh` подключается к консолям устройств в запущенном Cloud Provider Simulator.
Ему не нужны ресурсы игры или установленный Rust.

## Загрузка и запуск

Скачайте релизный ZIP-архив клиента и соответствующий ему файл `.zip.sha256`
из [раздела загрузок](/#downloads), выбрав релиз `game-ssh-v*` для своей платформы.

Пакеты Linux собираются на Ubuntu 22.04 для x86-64 с glibc. Пакеты Windows
собираются для x86-64 с помощью MSVC со статически скомпонованной библиотекой
времени выполнения C, поэтому распространяемый пакет Visual C++ не требуется.
Клиенту нужен терминал, графический рабочий стол не требуется.

Перед распаковкой ZIP-архива клиента при желании проверьте его в Linux:

```bash
sha256sum -c game-ssh-x86_64-unknown-linux-gnu.zip.sha256
```

В Windows сравните результат
`Get-FileHash game-ssh-x86_64-pc-windows-msvc.zip -Algorithm SHA256`
с контрольной суммой в файле `.sha256`.

Распакуйте ZIP-архив клиента. В Linux при необходимости выполните
`chmod +x game-ssh/game-ssh`. Затем запустите `./game-ssh/game-ssh --help`;
в Windows — `.\game-ssh\game-ssh.exe --help`. Также можно поместить исполняемый
файл в каталог из `PATH`.

## Подключение

Оставьте игру запущенной и включите удалённую консоль в настройках. Адрес
по умолчанию — `localhost:47655`. Используйте пароль, заданный в игре; клиент
запрашивает его со скрытым вводом. Если исполняемый файл доступен через `PATH`:

```bash
game-ssh --list
game-ssh 2
game-ssh 2 -c 'show version'
game-ssh --host localhost --port 51234 --list
```

Выберите устройство по идентификатору, имени, имени хоста или игровому
IPv4-адресу. Устройства должны быть включены. Подключение идёт напрямую
к симулируемой консоли. Игровой IP-адрес выбирает устройство без необходимости
иметь к нему сетевой путь внутри игры.

Tab дополняет команды; Ctrl-R ищет по истории. Введите `~.` или `logout`,
чтобы отключиться. Для использования в скриптах передавайте пароль через
`GAME_SSH_PASSWORD`. Это игровой клиент с интерфейсом, похожим на SSH,
и парольной аутентификацией поверх незашифрованного TCP, а не реализация
протокола SSH.

## Процесс сборки и выпуска

Рабочий процесс запускается при подходящих push в `main`, pull request
с целевой веткой `main`, ручных запросах **Run workflow** и отправке тегов
`game-ssh-v*`. Фильтры путей охватывают манифесты рабочего пространства,
код клиента и симуляции, встроенные JSON-файлы оборудования, скрипты упаковки
отдельного клиента, этот документ и сам рабочий процесс. Отправка тегов
запускает его независимо от фильтров путей.

До сборки выполняются тесты и Clippy для клиента и симуляции, проверка
форматирования рабочего пространства и тесты упаковки ZIP. В Linux также
выполняется интеграционный тест интерактивного терминала. Обе задачи нативной
сборки запускают тесты клиента, компилируют релизный исполняемый файл
и проверяют `--help`; Windows проверяет отсутствие нежелательных зависимостей
от DLL времени выполнения. Каждая задача загружает ZIP-архив, содержащий только
клиент и этот README, вместе с контрольной суммой SHA-256. Артефакты хранятся
30 дней. Сборки Cargo кешируются.

Необходимы включённый GitHub Actions и предоставляемые GitHub исполнители
Ubuntu 22.04/Windows. Рабочий процесс устанавливает стабильный Rust; Python 3,
GitHub CLI и инструменты Visual Studio C++ для Windows предоставляются образами
исполнителей. Секреты репозитория и внешний реестр не требуются. Задачи тестирования
и сборки используют `contents: read`; только задача выпуска по тегу использует
`contents: write` с автоматическим `GITHUB_TOKEN`. Политика репозитория или
организации должна разрешать этому токену создание релизов.

Чтобы опубликовать версию после включения рабочего процесса в репозиторий,
пометьте нужный коммит тегом:

```bash
git tag game-ssh-v0.1.0
git push origin game-ssh-v0.1.0
```

После успешных тестов и обеих сборок рабочий процесс публикует ZIP-архивы
и контрольные суммы в GitHub Release этого тега. Повторный запуск для тега
заменяет файлы его релиза. Релизы клиента не заменяют последний релиз игры
в репозитории. Запуски для веток, pull request и ручные запуски загружают
артефакты без публикации релиза.

# Аудит сетевых возможностей

Этот аудит проверяет реализацию и доступность функций для игрока. Он не
подтверждает совместимость с физическим оборудованием или полную совместимость
с IOS.

## Ошибки, исправленные во время аудита

- Дублирующиеся сохранённые записи WAN исправляются при загрузке и перезагрузке.
  Конфигурация нетегированного интерфейса и VLAN 1 теперь заменяет одну и ту же
  логическую запись, а ARP пропускает неназначенные записи-заглушки.
  Нетегированный трафик физического интерфейса остаётся работоспособным
  наряду с тегированными подинтерфейсами.

- Тегирование VLAN на маршрутизаторе теперь определяет активный конечный порт
  через пары пассивной патч-панели. ARP и маршрутизируемый трафик сохраняют теги
  при прохождении этого пути.
- Диагностика CDP обнаруживает активное сетевое устройство через патч-панель
  и безопасно пропускает разъёмы оператора, которые ранее могли вызывать panic
  из-за отсутствия устройства-владельца.
- DHCP и выделение собственных адресов используют общий расчёт резервирования,
  исключая адреса маршрутизаторов, серверов, оператора, управления и других аренд.
- `write memory` сохраняет снимок расширенной сетевой конфигурации выбранного
  устройства. Перезагрузка восстанавливает его привязки, сессии BGP, политики,
  предпочтения маршрутов, пулы DHCP, управление и состояние spanning tree.
  Другие устройства, запас адресов и конфигурация оператора сохраняются.
  Аренды не входят в стартовую конфигурацию.
- `management ip` коммутатора меняет фактический адрес управления, а не
  перекрывается конфигурацией сценария. Команда сохраняет существующие VLAN,
  префикс и шлюз и проверяет замену. `no management ip` удаляет адрес управления.
- `do ping` и `do traceroute` работают из режимов настройки. `show arp` и
  `show ip arp` показывают изученных соседей выбранного устройства вместе с VLAN.

Регрессионные проверки находятся в `crates/sim/tests/provider.rs`; существующие
тесты IOS покрывают обработку командных режимов и стартовую конфигурацию.

## Оптический физический уровень

Модули SFP/SFP+, оптические шнуры, DAC/AOC, патч-панели LC и аппаратные профили
10G теперь доступны в магазине и инспекторах портов. GUI и диагностика
Cisco/Linux используют тот же механизм оценки физического соединения,
что и пересылка пакетов и определение доступности ресурсов. Нарушения
ограничений дальности, полярности, длины волны, типа волокна, режима
и оптических потерь могут отключить физическое соединение.
Поддерживаемое оборудование и ограничения описаны в
[руководстве по оптическим сетям](OPTICAL_NETWORKING.md).
Регрессионные проверки находятся в `crates/sim/tests/optics.rs`;
для локализованных действий UI есть отдельные тесты
в `crates/game/src/ui/optics.rs`.

## Существующие функции с неполным доступом для игрока

| Функция | Текущий доступ | Недостающая работа |
| --- | --- | --- |
| Собственные диапазоны и обратные маршруты оператора | ДИАПАЗОНЫ IP | Заказ крупных/произвольных диапазонов и управление агрегатами |
| Адресация интерфейсов и VLAN | Инспектор и IOS | Подинтерфейсы native dot1q и полная грамматика виртуальных интерфейсов коммутатора |
| Статические маршруты | GUI каждого маршрутизатора и IOS | Дистанция маршрута IOS, маршруты только через интерфейс и синтаксис VRF; рекурсивное разрешение следующего узла |
| Домены маршрутизации | API сценариев; маршруты с учётом домена в GUI маршрутизатора | Редактор привязок интерфейсов каждого устройства и CLI VRF |
| BGP | API сценариев | Настройка каждого маршрутизатора и эксплуатационные команды |
| Фильтры пакетов/источников | API сценариев; Linux может настраивать собственные интерфейсы | Редактор ACL каждого устройства и CLI маршрутизатора/коммутатора |
| Пулы DHCP | API сценариев; Linux может настраивать собственные интерфейсы | UI/CLI настройки пулов маршрутизатора |
| Управление коммутатором | API сценариев и упрощённый `management ip` | GUI для VLAN/префикса/шлюза; стандартный CLI SVI; ping с коммутатора |
| Предотвращение петель | Автоматический детерминированный остовный лес | Управление приоритетом моста и состоянием портов для игрока; протокол BPDU |
| Расширенные стартовые настройки | Сохраняются и восстанавливаются для каждого устройства | Полное редактируемое текстовое представление в выводе текущей/стартовой конфигурации |
| Диагностика соседей | Таблица ARP IOS и серверные инструменты | Таблица MAC IOS, очистка соседей и управление временем их хранения |

Работающий API сценариев не означает, что игрок может настроить эту функцию
на маршрутизаторе. Недостающие элементы управления должны работать
с типизированной конфигурацией выбранного устройства и проверкой данных
в симуляции; они не должны создавать второе глобальное хранилище конфигурации
маршрутизаторов.

## Сохраняющиеся ограничения модели

- Порты LAN C1111 используют семантику маршрутизируемых портов. Встроенный
  коммутатор, домены мостов и SVI не моделируются. Сейчас поддерживается
  топология VLAN с маршрутизатором и внешним коммутатором.
- BGP проверяет условия работы и устанавливает семантические маршруты;
  он не создаёт сессии TCP, не обменивается сообщениями UPDATE, не обрабатывает
  полный набор атрибутов пути и не запускает таймеры.
- Spanning tree вычисляет лес после сходимости; обмена BPDU нет.
  Агрегация каналов, OSPF/IS-IS и IPv6 отсутствуют.
- DHCP имеет явные широковещательные и обратные пути, но не ретрансляторы
  и аренды с истекающим сроком. Состояние ARP/MAC сбрасывается при изменениях
  топологии/маршрутизации вместо устаревания по таймеру.
- Фильтрация IPv4/протоколов не отслеживает состояние, не поддерживает правила
  транспортных портов и отслеживание соединений. NAT отсутствует.
- Пропускная способность — диагностика физического пути без очередей,
  конкуренции за ресурсы, QoS и трафика перегрузки. Поведение волокна
  и трансиверов отсутствует.
- SSH в гостя — моделируемая консоль устройства. AAA, аутентификация устройств,
  поведение BMC и изоляция плоскости управления производственного уровня
  реализованы неполно.
- Диагностика использует явно заданные внешние лабораторные узлы.
  Она никогда не обращается к реальным сетям.

Поддерживаемый порядок настройки описан в
[руководстве по работе с провайдером](PROVIDER_NETWORK_GUIDE.md) и
[руководстве по командам IOS](IOS_GUIDE.md).

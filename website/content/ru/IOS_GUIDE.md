# Руководство по консоли коммутаторов и маршрутизаторов

В проекте реализован интерпретатор команд в стиле IOS, связанный с семантическим
симулятором сети. Он **не** запускает прошивку Cisco и не реализует всю
операционную систему IOS/IOS XE. Неподдерживаемые команды возвращают ошибку, а не
создают видимость успешного выполнения.

## Справочные материалы Cisco

Реализация следует общедоступному синтаксису команд и порядку работы с консолью,
описанным в следующих документах:

- [Catalyst 1000 IOS 15.2(7)Ex: использование интерфейса командной строки](https://www.cisco.com/c/en/us/td/docs/switches/lan/catalyst1000/software/releases/15_2_7_e/command_reference/b_1527e_1000_cr/using_the_command_line_interface.html)
- [Catalyst 1000: настройка транков VLAN](https://www.cisco.com/c/en/us/td/docs/switches/lan/catalyst1000/software/releases/15_2_7_e/configuration_guides/vlan/b_1527e_vlan_c1000_cg/configuring_vlan_trunks.html)
- [ISR 1000: использование Cisco IOS XE](https://www.cisco.com/c/en/us/td/docs/routers/access/1100/software/configuration/xe-17/isr1100-sw-config-xe-17/cisco_1100_series_swcfg_chapter_0100.html)
- [Руководство по настройке программного обеспечения ISR 1000](https://www.cisco.com/c/en/us/td/docs/routers/access/isr1100/software/configuration/guide/isr1100-sw-config.html)

Это внешние руководства производителя, а не прошивка в составе проекта и не
обещание поддержки всех описанных команд Cisco. Примеры ниже описывают
возможности, реализованные в этом симуляторе.

## Открытие консоли

Выберите коммутатор, маршрутизатор или один из его портов. Консоль появится под
стойкой. Включите питание устройства в инспекторе. Для подключения к консоли
не нужен Ethernet-кабель; Ethernet-кабели передают моделируемый трафик между
устройствами.

У каждого устройства свои строка ввода, история команд, вывод и командный режим.
Enter отправляет команду. Стрелки вверх/вниз вызывают команды из истории. Tab
дополняет однозначную команду с фиксированным синтаксисом или показывает
совпадающие варианты. `?` и `show ?` выводят доступные команды.
Ctrl-Z возвращает из режима настройки в привилегированный режим EXEC. Для
многострочных сценариев используйте **Вставить конфигурацию** и нажмите
**Выполнить**; выполнение останавливается при первой ошибке, сохраняя результат
предыдущих успешных строк. Сценарий не является транзакцией, но каждая отдельная
команда, в том числе для диапазона интерфейсов, выполняется атомарно.

## Командные режимы

| Приглашение | Режим | Как войти |
| --- | --- | --- |
| `Switch>` / `Router>` | Пользовательский EXEC | Начальная сессия консоли |
| `Switch#` | Привилегированный EXEC | `enable` |
| `Switch(config)#` | Глобальная настройка | `configure terminal` |
| `Switch(config-vlan)#` | Настройка VLAN | `vlan 20` |
| `Switch(config-if)#` | Настройка интерфейса | `interface Gi1/0/1` |
| `Switch(config-if-range)#` | Диапазон интерфейсов | `interface range Gi1/0/1 - 4` |
| `Router(config-subif)#` | Подинтерфейс маршрутизатора | `interface Gi0/1/6.20` |

`exit` выходит на один уровень настройки выше. `end` возвращает в
привилегированный EXEC. `disable` возвращает в пользовательский EXEC.
Поддерживаются однозначные сокращения ключевых слов, например `en`, `conf t`,
`int`, `no shut` и `sh ip int br`. Неоднозначные сокращения вызывают ошибку.
Команды `do show ...`, `do ping ...` и `do traceroute ...` можно выполнять, не
выходя из режима настройки. `do write memory` также сохраняет конфигурацию
из режима настройки.

## Имена интерфейсов

| Устройство | Имена в консоли | Обозначения в стойке |
| --- | --- | --- |
| Catalyst C1000 | `Gi1/0/1`–`Gi1/0/24` | `Gi1/0/01`–`Gi1/0/24` |
| Слоты Catalyst для SFP 1G | `Gi1/0/25`–`Gi1/0/28` | Установите модуль 1G через инспектор |
| Восходящие порты профилей Catalyst 10G | `Te1/0/1`–`Te1/0/4` | Слоты SFP+ 1/10G |
| WAN ISR C1111 | `Gi0/0/0`, `Gi0/0/1` | WAN1, WAN2 |
| LAN ISR C1111 | `Gi0/1/0`–`Gi0/1/7` | LAN1–LAN8 |
| Интерфейсы VLAN ISR C1111 | `Vlan1`–`Vlan4094` | Логические интерфейсы без кабельного разъёма |

Также работают полные имена `GigabitEthernet` и существующие обозначения на
стойке. Подинтерфейсы маршрутизатора принимают суффикс `.number`; перед
назначением IP-адреса выполните `encapsulation dot1q VLAN`. Номер подинтерфейса
и номер его VLAN могут различаться.

У новых маршрутизаторов C1111 два маршрутизируемых порта WAN и восемь
коммутируемых портов LAN. LAN7/8 (`Gi0/1/6`, `Gi0/1/7`) — гибкие порты:
`no switchport` переводит их в маршрутизируемый режим; `switchport` возвращает
режим доступа уровня 2 и очищает их конфигурацию маршрутизации.
Фиксированные порты LAN маршрутизируют через `interface Vlan<N>`. Принадлежность
к access/trunk и изоляция VLAN используют общий механизм коммутации.
`ip routing` включён по умолчанию; `no ip routing` прекращает пересылку
транзитного трафика, сохраняя доступность локальных адресов и коммутацию LAN.
Роли портов, поддержка гибких портов и маршрутизация по умолчанию задаются
в блоке `network` JSON-файла маршрутизатора.

Интерфейс VLAN становится активным после `no shutdown`, когда его VLAN
существует и содержит активный порт LAN. У него нет физического кабельного
разъёма. VLAN, интерфейсы и состояние маршрутизации сохраняются в сохранениях
игры и при `write memory`/`reload`. Старые сохранения сохраняют прежние
конфигурации маршрутизируемых портов LAN. Аппаратные ограничения соответствуют
[руководству Cisco по коммутируемым и гибким портам ISR](https://www.cisco.com/c/en/us/td/docs/routers/access/isr1100/software/configuration/guide/isr1100-sw-config/configuring_ethernet_switchports.html),
в том числе ограничению двумя гибкими портами, введённому в IOS XE 17.11.1a.

## Пример: две серверные VLAN через маршрутизатор

Установите и включите один коммутатор, один маршрутизатор и два сервера.
Подключите сервер A к порту 1 коммутатора, сервер B — к порту 2, а LAN7
маршрутизатора — к порту 3.

Выполните на коммутаторе, начиная с `Switch>`:

```text
enable
configure terminal
hostname Core
vlan 20
name Servers
exit
vlan 30
name Services
exit
interface Gi1/0/1
description Server A
switchport mode access
switchport access vlan 20
no shutdown
exit
interface Gi1/0/2
description Server B
switchport mode access
switchport access vlan 30
no shutdown
exit
interface Gi1/0/3
description Router LAN7
switchport mode trunk
switchport trunk allowed vlan 20,30
no shutdown
exit
end
write memory
```

Выполните на маршрутизаторе, начиная с `Router>`:

```text
enable
configure terminal
hostname Edge
interface Gi0/1/6
no switchport
exit
interface Gi0/1/6.20
encapsulation dot1q 20
ip address 10.0.20.1 255.255.255.0
exit
interface Gi0/1/6.30
encapsulation dot1q 30
ip address 10.0.30.1 255.255.255.0
exit
interface Gi0/1/6
no shutdown
exit
end
copy running-config startup-config
```

В инспекторе назначьте серверу A адрес `10.0.20.2/24`, шлюз `10.0.20.1`, VLAN
20. Серверу B назначьте `10.0.30.2/24`, шлюз `10.0.30.1`, VLAN 30.
В терминале сервера A команда `ping 10.0.30.2` проверяет маршрутизацию, а
`ping 10.0.20.1` — доступность шлюза. В консоли маршрутизатора можно выполнить
`ping 10.0.20.2` или `traceroute 10.0.30.2`.

Само подключение кабеля к WAN1 не обеспечивает доступ в Интернет. Настройте
доставку диапазона через транзитное подключение в **ДИАПАЗОНАХ IP** и явно
задайте прямые и обратные маршруты в редакторе **Таблица маршрутизации…**
каждого маршрутизатора. Для приведённых выше примеров с частными адресами NAT
автоматически не применяется. См. [работу с сетью провайдера](PROVIDER_NETWORK_GUIDE.md).
Пакеты в Интернет через сеть компьютера не отправляются.

## Статические маршруты из консоли маршрутизатора

В режиме глобальной настройки добавьте маршрут по умолчанию через шлюз
вышестоящей сети, указанный в **ДИАПАЗОНАХ IP**:

```text
enable
configure terminal
ip route 0.0.0.0 0.0.0.0 192.0.2.5
end
show ip route
ping 192.0.2.5
ping 8.8.8.8
write memory
```

Следующий узел выбирает наиболее специфичный настроенный интерфейс с прямым
подключением в домене маршрутизации 0. Если несколько интерфейсов подходят
одинаково, укажите интерфейс явно:
`ip route 0.0.0.0 0.0.0.0 Gi0/0/0 192.0.2.5`.
Для удаления используйте `no ip route NETWORK MASK NEXT-HOP` или вариант
с интерфейсом. Маршруты отображаются в GUI, `show ip route` и
`show running-config`; `write memory` сохраняет их для перезагрузки.
Из настройки одного интерфейса можно сразу перейти к другому командой
`interface NAME`.

## Поддерживаемая настройка

- Глобально: `hostname NAME`, `no hostname`, `vlan ID`, `no vlan ID`, `interface
  NAME`, `interface range Gi1/0/1 - 4`. В режиме VLAN: `name NAME`.
- Интерфейсы: `description TEXT`, `no description`, `shutdown`, `no shutdown`.
  Отключение действует на физические порты вместе со всеми их подинтерфейсами.
- Порты коммутатора: `switchport mode access`, `switchport access vlan ID`,
  `no switchport access vlan`, `switchport mode trunk`,
  `switchport trunk native vlan ID`, `switchport trunk allowed vlan LIST`,
  а также операции со списком разрешённых VLAN `add LIST` / `remove LIST`.
- Глобальные маршруты маршрутизатора: `ip route NETWORK MASK NEXT-HOP`,
  `ip route NETWORK MASK INTERFACE NEXT-HOP` и их варианты с `no`.
- Интерфейсы маршрутизатора: `ip address ADDRESS MASK`, `no ip address`;
  подинтерфейсы дополнительно поддерживают `encapsulation dot1q ID`.
- Физические интерфейсы поддерживают `speed 10`, `speed 100`, `speed 1000`,
  `speed 10000`, `speed 25000` и `speed auto` — максимальную скорость порта,
  используемую по умолчанию. Скорости, не поддерживаемые портом, отклоняются.
  Настроенное объявление скорости сохраняется командой `write memory`;
  для оптического соединения требуется общий режим порта и модуля.
- `show inventory`, `show interfaces transceiver` и
  `show interfaces Te1/0/25 transceiver` показывают установленные модули,
  подключённые концы кабелей, оптическую мощность TX/RX по DOM, когда она
  доступна, и общую диагностику физической неисправности соединения.
  Оборудование устанавливается через GUI независимо от стартовой конфигурации.
  На Linux-серверах для той же диагностики модулей используется
  `ethtool -m INTERFACE`.

Допустимые номера VLAN — 1–4094. Списки принимают `20,30-35`, `all` или `none`.
Перед изменением разрешённых VLAN или native VLAN настройте режим trunk.
Изначально транки разрешают все VLAN, но для пересылки VLAN должна существовать
в базе коммутатора. Назначение access VLAN создаёт её, если она отсутствует.
VLAN 1 удалить нельзя.

Текущая модель порта хранит только активный режим switchport. При переключении
из trunk в access номер access VLAN сбрасывается на 1; возврат в trunk
восстанавливает список разрешённых VLAN по умолчанию, а не ранее настроенный
неактивный профиль trunk. Пересылка access/trunk применяет теги VLAN и
преобразование native VLAN в механизме Ethernet. Для нетегированного адреса
сервера привязку к VLAN можно не задавать.

## Проверка конфигурации и соединений

```text
enable
show version
show running-config
show running-config interface GigabitEthernet0/0/0
show startup-config
show vlan brief
show interfaces
show interfaces status
show interfaces Gi1/0/1
show interfaces Gi1/0/1 switchport
show interfaces trunk
show ip interface brief
show ip route
show ip arp
show cdp neighbors
```

Для просмотра конфигурации требуется привилегированный EXEC (`#`); из `>`
выполните `enable`. `show running-config interface NAME` показывает только блок
конфигурации указанного интерфейса: физического порта, SVI, подинтерфейса или
port-channel. Работают сокращения, например `sh run int Gi0/0/0`. Это соответствует
[команде Cisco для отображения конфигурации](https://www.cisco.com/c/en/us/td/docs/switches/lan/catalyst9400/software/release/16-8/command_reference/b_168_9400_cr/b_168_9400_cr_chapter_010011.html).

Вывод вычисляется по состоянию симулятора. Статус интерфейса учитывает питание,
установку оборудования, административное отключение, длину кабеля и его удалённый
конец; столбец скорости показывает согласованную скорость для активного
соединения и локально объявленную скорость для неактивного.
Вывод CDP определяет активные соседние сетевые устройства по топологии;
симулятор не обменивается пакетами CDP и не учитывает срок их действия.
Диагностика маршрутизатора поддерживает непосредственно подключённые адресаты
и явно настроенные транзитные пути. Traceroute показывает семантические узлы
пути, а не измеренные задержки пакетов. Коммутаторы не могут отправлять ping,
поскольку диагностика с коммутатора не реализована; их адреса управления могут
принимать ping и SSH через реально существующий сетевой путь.

## Сохранение и перезагрузка

`write memory` и `copy running-config startup-config` сохраняют конфигурацию
выбранного устройства внутри симуляции. `reload` запрашивает подтверждение:
нажмите Enter, чтобы восстановить стартовую конфигурацию, или введите `cancel`,
чтобы оставить текущее состояние. Несохранённые изменения удаляются только после
подтверждения. Для перезагрузки нужна сохранённая стартовая конфигурация.
Размещение в стойке, питание, кабели, деньги и другие устройства сохраняются.
Также восстанавливаются привязки доменов маршрутизации, сессии BGP, фильтрация,
пулы DHCP, настройки управления коммутатором и spanning tree выбранного
устройства. Договоры доставки с оператором и запас адресов остаются независимыми.
Аренды DHCP и изученные записи ARP относятся к оперативному состоянию, а не к
стартовой конфигурации. Старые стартовые записи без нового снимка сети сохраняют
прежнее поведение при перезагрузке.

После выполнения команд нажмите **Сохранить** в игре, чтобы записать симуляцию,
включая текущие и стартовые конфигурации, в SQLite. **Загрузить** восстанавливает
эти конфигурации и начинает новые сессии консоли. Переключение питания в этом
симуляторе сохраняет текущую конфигурацию; для восстановления стартовой
используйте `reload`.

## Границы совместимости

Это функциональное подмножество команд IOS. Загрузка прошивки,
аутентификация/AAA, IPv6, настраиваемый IOS NAT и OSPF/EIGRP не моделируются.
Для Catalyst EtherChannel, QoS и SNMPv2c реализованы функциональные подмножества
симуляции; команды и точные ограничения приведены в
[руководстве по Catalyst](CATALYST_SWITCHES.md).
Механизм пакетов Ethernet/IPv4 поддерживает пересылку по статическим маршрутам.
Политики BGP провайдера, пересылка после сходимости spanning tree, фильтрация
интерфейсов, управление коммутатором и семантический DHCP имеют API настройки
сценариев; полная грамматика их команд IOS и обмен протокольными сообщениями
не реализованы. Неподдерживаемые команды IOS явно завершаются ошибкой.
Для интерфейсов устройств используйте инспектор, для статических маршрутов —
редактор маршрутизации маршрутизатора, для доставки выделенных диапазонов
и инструкций по адресации WAN/LAN — **ДИАПАЗОНЫ IP**. `show ip route` включает
статические маршруты, настроенные в GUI.

Регрессионные тесты охватывают режимы консоли, недопустимые и неоднозначные
команды, изоляцию сессий устройств, атомарность ошибки диапазона интерфейсов,
коммутацию VLAN, маршрутизируемые VLAN, ping шлюза, фильтрацию транков,
отключение интерфейсов, восстановление стартовой конфигурации и сохранение
в SQLite.

## Пример: VLAN 8 на встроенном коммутаторе маршрутизатора

```text
enable
configure terminal
vlan 8
name SERVERS
exit
interface Gi0/1/0
switchport mode access
switchport access vlan 8
exit
interface vlan 8
ip address 10.0.8.1 255.255.255.0
no shutdown
exit
ip routing
end
write memory
```

Узел на LAN1 может использовать `10.0.8.1` как шлюз. Добавьте ещё одну VLAN
и интерфейс для маршрутизации между LAN; трафик внутри одной VLAN коммутатор
пересылает без маршрутизации.

# Диагностика хостинга

Проверяйте путь по порядку, чтобы найти причину.

1. **Установка и питание:** устройства стоят в стойке, подключены и включены?
2. **Физический линк:** кабеля недостаточно; проверьте состояние разъёмов.
3. **L2:** совпадают access VLAN либо теги и allowed list trunk-портов?
4. **IP:** адреса уникальны, маски и интерфейс источника верны?
5. **Маршруты:** доступны следующий шлюз, default route и обратный путь?
6. **Сервис:** контроллер активен, узел правильно зарегистрирован?
7. **Размещение:** хватит ресурсов и адресов, работают правила гостевой подсети?
8. **Спрос:** время и поток клиентов идут, тариф платный и привлекательный?

Диагностика Linux:

```sh
ip -br addr
ip route
ip route get 10.0.10.10
ping -c 3 10.0.10.10
traceroute 8.8.8.8
systemctl status hosting-provider
vm-host status
```

Команды `hosting-provider` относятся к контроллеру, `vm-host` — к узлу ВМ.
На сетевых устройствах используйте подходящие `show interfaces status`,
`show vlan brief`, `show ip interface brief`, `show ip route`, `show running-config`.

Подсказки текущих задач Wiki помогут выбрать проверку. Достижение первой продажи
историческое; оно не гарантирует исправность сети после последующих изменений.

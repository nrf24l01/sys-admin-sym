# Проверьте связь через ping

`ping` отправляет ICMP echo-запросы и ожидает ответы. Успех проверяет вместе
источник, кабели, VLAN, адресацию и обратный путь. Один горящий индикатор этого
не гарантирует.

## На узле ВМ

```sh
ip route get 10.0.10.10
ping -c 3 -I eth1 10.0.10.10
```

## На контроллере

```sh
ip route get 10.0.10.11
ping -c 3 -I eth1 10.0.10.11
```

Обе стороны должны получать ответы. `ip route get` должен выбирать частный
интерфейс управления. Руководство проверяет текущую доставку пакетов, а не факт
ввода команды: неудачный ping не завершает задачу.

Если связи нет, проверяйте по порядку: установка и питание; состояние линков;
одинаковая VLAN; уникальные адреса в одной подсети; правильный интерфейс маршрута.

```sh
ip -br addr
ip link show
ip route
ip neigh show dev eth1
```

На коммутаторе используйте `show interfaces status` и `show vlan brief`.
Для связи внутри одной подсети не нужен публичный маршрут по умолчанию.

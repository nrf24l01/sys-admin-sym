# Подключите публичную витрину

Контроллеру нужен свободный публичный IP из купленного диапазона и рабочие прямой
и обратный маршруты. В примере используйте `203.0.113.2/29` со шлюзом
`203.0.113.1`. Частный адрес `10.0.10.10/24` остаётся на интерфейсе управления.

## На контроллере

```sh
ip addr add 203.0.113.2/29 dev eth0
ip link set dev eth0 up
ip route replace default via 203.0.113.1 dev eth0
ping -c 3 203.0.113.1
ping -c 3 8.8.8.8
systemctl status hosting-provider
```

Используйте свои значения диапазона. `8.8.8.8` — диагностический узел симуляции;
ваш компьютер не отправляет туда сетевые пакеты. Если шлюз отвечает, а внешний
узел нет, проверьте default route маршрутизатора, WAN и доставку диапазона.

Обновите `/etc/network/interfaces` для восстановления обеих сетей при reboot:

```text
auto lo eth0 eth1
iface lo inet loopback
iface eth0 inet static
    address 203.0.113.2/29
    gateway 203.0.113.1
iface eth1 inet static
    address 10.0.10.10/24
```

Примените `systemctl restart networking`. В **ХОСТИНГ → Сайт провайдера** введите
**только** `203.0.113.2` и подключите хостер. Игра найдёт физический сервер с этим
адресом. Поле не принимает URL, путь или частный адрес. Должны работать и сервис,
и публичная сеть с обратным маршрутом.

Недоступность витрины останавливает новые продажи. Управление и трафик работающих
гостей используют отдельные пути; сохраняйте сеть управления исправной.
